# Land it or regenerate it: two rules point opposite ways at the same file

## Context

**From the 2026-08-22 cold drill** (STORY-016 § Provenance).

For a **generated** file that is **uncommitted** *and* carries content its verb cannot reproduce, two
rules give opposite instructions and neither states precedence:

- `LAYER.md:133-138` — tracking is orthogonal to the *already present?* column, so `present, uncommitted`
  adds an **offer to land it** on top of whatever the row says.
- `adopt-project` § 3c — a generated file gets **render, compare, and only then write**, and its third
  row says content the verb cannot reproduce would be removed ⇒ **stop**.

Landing means committing the file as it stands. Regenerating means overwriting it. Both are "what to do
about this file", and they cannot both happen.

**Hit on this repo's own `tasks/README.md`** during the drill's Run C: modified, uncommitted, and
carrying a parent-status narrative no verb derives. The drill offered only to **land** it — which changes
nothing inside the file — and explicitly declined to regenerate, leaning on § 3c's stop row. It flagged
that nothing told it that was the right precedence.

**Its resolution is probably correct and that is exactly why the rule should say so.** Landing is
information-preserving and reversible; regenerating destroys content nobody can reconstruct. An agent
that reasoned the other way — "it is generated, so regenerate it, then commit" — would have been
following an equally readable path to data loss.

Small, and worth doing for that reason: it is one precedence sentence in a place where the wrong branch
is unrecoverable.

## Acceptance criteria

- [ ] The precedence is stated where an agent hits the conflict — landing wins over regenerating for a generated file carrying non-derivable content, or whatever the deliberate answer turns out to be
- [ ] The reason travels with the rule: one direction is reversible and the other is not
- [ ] The rule is stated once and pointed at from the other side, not written into both `LAYER.md` and `adopt-project` § 3c
- [ ] § 3c's stop-on-unreproducible-content row still holds — this must not become a licence to overwrite
- [ ] `bash .github/workflows/skills-lint.sh` passes
