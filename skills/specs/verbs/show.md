# /specs show — print one area's spec

Read-only view of a single capability spec.

## Steps

1. **Find project root + load `.map.yml`.** No map, or a map whose `areas:` list is empty → `No usable spec map — run /specs init to bootstrap.` and exit, as the router does.
2. **Resolve the area** — exact `name` match first, then unambiguous prefix/substring. No area given, ambiguous or unknown → **list the map's areas and stop**: one `<name> — <title>` line per area, in map order, then one `not covered: <job> — <why>` line per `not-covered:` entry ([SKILL.md](../SKILL.md) § *The area map*). Print the lines as they are and nothing else: a name is kebab-case and a job holds no ` — `, so the first ` — ` on a line ends it, whatever dashes the title or reason carries. The second part is printed whenever the key holds entries, because this list is where a reader picks an area, and a job missing from it without a reason reads as a hole.
3. **Print** the body of `docs/specs/<area>.md` (everything below its frontmatter, as written) under a **one-line header made of the frontmatter's values**: `<area> · generated <generated-on> · shaped-by: <ids>`, the ids comma-separated, e.g. `specs-from-code · generated 2026-11-15 · shaped-by: FEATURE-003, FEATURE-005`. Only `shaped-by` keeps its label, because its value can be a sentence rather than ids; a derived list that is empty prints `shaped-by: none`, since derivation ran and found nothing, which is not the unknown case below. When `shaped-by-derived:` is `false` or absent, render the provenance as **`shaped-by: (never derived)`** rather than as an empty list — an un-derived field is unknown, not empty, and a reader must not take `[]` at face value. Suggest filling it in that header line itself, after the field: `shaped-by: (never derived — /specs regen <area> fills it)`, so the suggestion sits beside the gap and nowhere else. When it *was* derived but `shaped-by-unresolved:` is non-zero, append **`(N tasks left no evidence)`** — a partial answer shown as a plain list reads as a complete one.
4. **Freshness footer** — run the [verify](verify.md) staleness check for just this spec and append one line: `fresh ✓ (as of <generated-on>)` or `⚠ stale — <k> sources changed since <anchor short sha> → /specs regen <area>` (`1 source changed` for one; the sha is always its first 7 characters, `git rev-parse --short=7`, since git's default abbreviation grows with the repository and two runs would print two lengths), where the anchor is the one [verify](verify.md) step 3 resolved (the later of `generated-at` and the spec's own last commit), never `generated-at` read on its own. An unresolvable anchor prints `⚠ stale — unknown baseline → /specs regen <area>`.
5. **No spec file yet** (mapped but never generated) → say so and suggest `/specs regen <area>`.
